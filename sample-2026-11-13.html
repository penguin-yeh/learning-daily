Aho-Corasick 自動機：多模式字串匹配

今天換一個全新類別：多模式字串匹配（Multi-Pattern Matching）。給定一組模式字串 {p₁, p₂, ..., pₖ}（例如敏感詞清單、病毒特徵碼、路由規則），以及一段長文字 S，目標是「同一次掃描」就找出所有模式分別出現在 S 的哪些位置。這跟 KMP 解的「單一模式」問題本質不同：天真的作法是對每條模式各跑一次 KMP，但這樣會重複掃描文字 k 次，當 k 很大（例如一萬條惡意網域黑名單）時就很浪費。

Aho-Corasick 的第一步是把所有模式字串插入同一棵

Trie（字典樹）　一種每個節點代表一段共同前綴的樹狀結構；多個字串共享的前綴會共用同一條路徑，是字首查詢最經典的資料結構。
裡，並在模式結尾的節點標記 output=true。第二步是對 trie 做 BFS，為每個節點建立失敗連結（fail link），意義與 KMP 的 failure function 一致：前綴比對失敗時，退到次佳的已知前綴繼續比。有了 fail link 之後，文字每讀一個字元就轉移一次，永遠不會往回看，這正是它比暴力解法快的核心。

複雜度比較：設文字長度 n、k 個模式、總長度 m、實際匹配數 z。暴力解法是 O(n·m)；對每個模式各跑一次 KMP 是 O(k·n + m)；Aho-Corasick 建構 O(m·Σ)，查詢只需 O(n + z)。

🔢 數學推導

為什麼查詢階段是 O(n+z) 而不是 O(n·depth)？關鍵在攤銷分析：每次成功往前走一步，狀態的深度最多 +1；每次退回 fail link，深度一定嚴格下降。所以讀 n 個字元，深度最多上升 n 次、也最多下降 n 次，所有退回步數加總不會超過 O(n)。

Ch.4　4.1 The Y86-64 Instruction Set Architecture

第三章講完完整的 x86-64 機器碼之後，第四章要帶我們動手「做」一顆處理器——但真正的 x86-64 指令集太龐大，一學期內不可能完整實作。作者因此設計了 Y86-64：一個指令數量大幅精簡、但保留足夠真實感的教學用 ISA。

指令編碼第一個 byte 拆成兩個 nibble：高 4 位是 icode（指令類別），低 4 位是 ifun（同一類別下的功能變形）。需要暫存器運算元的指令接著第二個 byte：高 4 位放 rA、低 4 位放 rB，不需要的欄位一律填 0xF。例如把 0x100 存進 %rdx 的 irmovq，完整編碼是 30 F2 00 01 00 00 00 00 00 00，其中立即數以小端序排列。

🔢 數學推導

為什麼 register 欄位用 4 bit？2⁴=16 剛好能編碼 16 個值，Y86-64 用掉 15 個，第 16 個值（0xF）保留當 sentinel。第一個 byte 拆成 4+4 的 nibble，則是為了在 1 個 byte 內同時表達「類別」與「變化」。

解析 Linux 共享記憶體機制：SysV／POSIX／memfd_create／dma_buf 全景比較

承接 11/08 教過的 POSIX Shared Memory，今天把視角拉高，看 Linux 歷史上為了「讓多個行程共用同一塊實體記憶體、省掉 memcpy 拷貝開銷」這個目標，陸續長出哪些彼此並不相容的機制。共通目標都是

zero-copy（零拷貝）　讓資料只存在一份實體記憶體，透過映射（而非複製）讓多方都能直接存取。
。

SysV 共享記憶體最早：用 shmget／shmat／shmdt，key 是全域命名空間，生命週期不會跟著行程結束，必須手動 ipcrm。POSIX 共享記憶體用 shm_open 回傳普通 fd，底層由 /dev/shm 的 tmpfs 撐住。memfd_create（Linux 3.17）回傳不綁定路徑的匿名記憶體 fd，還能加上 file sealing 防止對方事後改大小或內容。dma_buf 則處理裝置之間的 buffer 共享，例如 camera 驅動匯出、GPU 驅動匯入。

struct dma_buf_ops {
	/* 可選（optional）*/
	int (*attach)(struct dma_buf *, struct dma_buf_attachment *);

	/* 必要（mandatory）*/
	struct sg_table * (*map_dma_buf)(struct dma_buf_attachment *,
					  enum dma_data_direction);

	/* 於最後一次 dma_buf_put 之後呼叫，必要 */
	void (*release)(struct dma_buf *);

	/* 可選，讓 CPU 端也能直接 mmap 存取 */
	int (*mmap)(struct dma_buf *, struct vm_area_struct *vma);
};
